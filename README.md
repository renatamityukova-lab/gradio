# Список покупок по блюду (Gradio)

Минимальное Gradio-приложение: пользователь указывает блюдо, количество человек
и формат ответа — приложение формирует запрос к LLM и показывает список покупок.

## Возможности

- поле ввода блюда (многострочный текст);
- выбор количества человек: 1 / 2 / 4 / 6;
- формат ответа: «Список продуктов» или «Список + шаги»;
- кнопка «Сгенерировать список покупок»;
- валидация ввода до обращения к API;
- обработка ошибок API без traceback в интерфейсе.

```

    ├── .gitignore          # исключения git для этого репозитория
    ├── .gitattributes
    ├── gradio_app.py       # UI (Gradio Blocks) и обработчик кнопки
    ├── prompts.py          # system/user-промпты, формат и количество человек
```

> `ПроектVSC` на этот репозиторий не действует, поэтому защита секретов
> описана в [`gradio/.gitignore`](.gitignore).

Ответственность модулей:

| Файл | Назначение |
|---|---|
| [`gradio_app.py`](gradio_app.py) | интерфейс и связка «ввод → обработчик → вывод» |

## Требования

- Python 3.11+ (проверено на 3.11.3);
- доступ к корпоративному LLM-шлюзу и API-ключ;
- Windows `cmd` — команды ниже даны для него. В bash/zsh замените
  `.venv\Scripts\...` на `.venv/bin/...`, а `set` — на `export`.

## Установка

Все команды — из корня проекта (`ПроектVSC`), где лежит каталог `gradio`.

1. Создать окружение (если его ещё нет):

```cmd
python -m venv .venv
```

2. Активировать:

```cmd
.venv\Scripts\activate
```

3. Установить зависимости:

```cmd
pip install -r gradio\requirements.txt
```

> В `requirements.txt` закреплены `numpy<2` и `pandas<2.3`: на этом окружении
> NumPy 2.x падает с `ImportError: DLL load failed`, а pandas 3.x требует NumPy ≥ 2.

4. Создать локальные настройки:

```cmd
copy gradio\.env.example gradio\.env
```

5. Открыть `gradio/.env` и заменить `OPENAI_API_KEY=your_api_key_here` на реальный ключ.
   Файл `.env` в git не попадает.

## Переменные окружения

| Переменная | Обязательна | Значение по умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | да | — |
| `LLM_MODEL` | нет | `gpt-oss-120b` |
| `LLM_FALLBACK_MODEL` | нет | — (резервная модель) |
| `LLM_BASE_URL` | нет | `https://llm.enplus.group/v1` |
| `LLM_FALLBACK_BASE_URL` | нет | — (тот же шлюз) |
| `LLM_TRUST_ENV` | нет | `true` (учитывать HTTP(S)_PROXY) |
| `LLM_MAX_RETRIES` | нет | `1` (один повтор для временных ошибок) |
| `LLM_TIMEOUT_SECONDS` | нет | `60` |
| `LLM_TEMPERATURE` | нет | `0` |

## Запуск

Из корня проекта `ПроектVSC`:

```cmd
.venv\Scripts\python.exe gradio\gradio_app.py
```

Либо с активацией окружения:

```cmd
.venv\Scripts\activate
python gradio\gradio_app.py
```

После старта откройте адрес, который выведет Gradio (обычно
**http://127.0.0.1:7860**). Остановка — `Ctrl+C`.

Если порт занят, задайте другой:

```cmd
set GRADIO_SERVER_PORT=7861
.venv\Scripts\python.exe gradio\gradio_app.py
```

Каталог запуска не важен: модули берутся из папки скрипта, а `.env` ищется
относительно `gradio_app.py`.

## Как это работает

1. `generate_shopping_list(dish, people, format)` в [`gradio_app.py`](gradio_app.py);
2. `validate_dish()` в [`validation.py`](validation.py) — пустой ввод и лимит длины;
3. `build_messages()` в [`prompts.py`](prompts.py) — system-промпт и user-промпт
   с явными количеством человек и форматом;
4. `complete(messages)` в [`llm_client.py`](llm_client.py) — POST на
   `{LLM_BASE_URL}/chat/completions`, при необходимости резервная модель;
5. результат или безопасное сообщение об ошибке возвращается в поле «Результат».

### Форматы ответа

- **Список продуктов** — только список, каждый продукт отдельной строкой с «- »;
- **Список + шаги** — список продуктов, затем 5–8 коротких нумерованных шагов.

### Валидация ввода

| Условие | Сообщение |
|---|---|
| пустой текст или только пробелы | «Напишите, что хотите приготовить.» |
| больше 500 символов | «Слишком длинный текст — сократите или разбейте на части.» |

При ошибке валидации запрос к API не отправляется.

### Карта ошибок API

| Ситуация | Сообщение в интерфейсе | Повторы |
|---|---|---|
| 4xx (доступ/настройка, в т.ч. нет ключа) | «Не настроен доступ к сервису.» | нет |
| 5xx и 429 | «Сервис временно недоступен. Попробуйте позже.» | 1 |
| таймаут или сеть | «Не удалось получить ответ. Попробуйте ещё раз.» | 1 |
| пустой/битый ответ модели | «Пустой ответ модели. Попробуйте переформулировать вопрос.» | нет |

Технические детали (модель, HTTP-статус, фрагмент тела) пишутся в консоль,
в интерфейс попадает только сообщение из таблицы.

## Тест-сценарии

### Ручная проверка в интерфейсе

| № | Шаги | Ожидаемый результат |
|---|---|---|
| 1 | Оставить поле пустым, нажать кнопку | «Напишите, что хотите приготовить.»; запрос к API не уходит |
| 2 | Ввести только пробелы, нажать кнопку | То же сообщение, что в п. 1 |
| 3 | Ввести текст длиннее 500 символов | «Слишком длинный текст — сократите или разбейте на части.» |
| 4 | Ввести ровно 500 символов | Валидация проходит, запрос отправляется |
| 5 | «борщ», 2 человека, «Список продуктов» | Только список покупок, по продукту на строку, без шагов |
| 6 | «борщ», 4 человека, «Список + шаги» | Список покупок + 5–8 коротких нумерованных шагов |
| 7 | Одно блюдо при 1 и при 6 человеках | Количества продуктов различаются |
| 8 | Временно заменить один символ в `OPENAI_API_KEY`, нажать кнопку | «Не настроен доступ к сервису.», без traceback; вернуть ключ |
| 9 | Временно указать неверный `LLM_BASE_URL`, нажать кнопку | «Не удалось получить ответ. Попробуйте ещё раз.», без traceback |
| 10 | Во время генерации смотреть на кнопку | Кнопка блокируется, показывается индикатор загрузки |

После сценариев 8–9 верните исходные значения в `gradio/.env`.

### Минимальный набор: 3 проверки

1. **Успешный сценарий.**
   Введите `борщ`, выберите `2` человека и формат `Список продуктов`, нажмите
   «Сгенерировать список покупок».
   Ожидаемо: список покупок, каждый продукт с новой строки с «- », без шагов.

2. **Пустой ввод.**
   Очистите поле и нажмите кнопку.
   Ожидаемо: «Напишите, что хотите приготовить.», запрос к API не уходит.

3. **Ошибка доступа (ключ убран).**
   Выполните шаги из раздела «Как воспроизвести ошибку: убрать ключ».
   Ожидаемо: «Не настроен доступ к сервису.», без traceback в интерфейсе.

### Как воспроизвести ошибку: убрать ключ

1. Остановите приложение: `Ctrl+C` в терминале.
2. Откройте `gradio/.env` и закомментируйте строку с ключом, поставив `#` в начало:

   ```
   # OPENAI_API_KEY=ваш_ключ
   ```

   Допустимый вариант — оставить пустое значение: `OPENAI_API_KEY=`.
3. Запустите приложение снова:

   ```cmd
   .venv\Scripts\python.exe gradio\gradio_app.py
   ```

   Перезапуск обязателен: переменные уже загружены в процесс, правка `.env`
   на лету не применится.
4. Введите `борщ`, выберите `2` человека и любой формат, нажмите кнопку.
5. Ожидаемо: в поле «Результат» — **«Не настроен доступ к сервису.»**,
   в интерфейсе нет traceback, запрос к API не отправляется.
6. Верните строку ключа в исходное состояние (уберите `#` или впишите ключ)
   и снова перезапустите приложение — успешный сценарий должен восстановиться.

Ту же ошибку можно воспроизвести, заменив один символ в ключе: сервис ответит
4xx, и приложение покажет то же сообщение без повторов.

### Автоматические проверки

Синтаксис модулей:

```cmd
.venv\Scripts\python.exe -m py_compile gradio\gradio_app.py gradio\llm_client.py gradio\prompts.py gradio\validation.py
```

Проверка конфигурации (ключ не выводится, печатается только его длина):

```cmd
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'gradio'); import llm_client as l; c=l.load_config(); print(c.model, c.fallback_model, c.base_url, len(c.api_key))"
```

Ожидаемо: `gpt-oss-120b MiniMax-M2.7 https://llm.enplus.group/v1 25`.

Проверка валидации без сети:

```cmd
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'gradio'); from validation import validate_dish; print(validate_dish('  ')); print(validate_dish('а'*501)); print(validate_dish('борщ'))"
```

Ожидаемо: два сообщения об ошибках и `None`.

Живой запрос к модели (расходует токены, первый ответ может идти до 60 с):

```cmd
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'gradio'); import llm_client as l; print(l.complete([{'role':'user','content':'Ответь одним словом: тест'}])[:200])"
```

## Безопасность

- ключ хранится только в `gradio/.env`, в коде и в git его нет;
- `.env` исключён локальным [`gradio/.gitignore`](.gitignore): правила `.env`,
  `.env.*` и `!.env.example`; корневой `.gitignore` здесь не применяется,
  так как `gradio` — отдельный репозиторий;
- ключ не пишется в логи и не попадает в сообщения об ошибках — только в заголовок
  `Authorization` при запросе;
- промпты в логи не выводятся.

Проверить, что `.env` не попадёт в коммит:

```cmd
git check-ignore -v .env
git ls-files | findstr /i ".env"
```

Ожидаемо: первая команда показывает правило из `.gitignore`, вторая — только
`.env.example`.

### Если `.env` уже попал в git

`.gitignore` не удаляет файл из истории. Если `.env` был закоммичен:

1. отзовите ключ и выпустите новый — старый считайте скомпрометированным;
2. уберите файл из индекса, сохранив его локально:

   ```cmd
   git rm --cached .env
   git add .gitignore
   git commit -m "Убрать .env из репозитория"
   git push
   ```

3. очистите историю (`git filter-repo --path .env --invert-paths`) или
   пересоздайте репозиторий, затем сделайте `push --force`;
4. включите на GitHub *Settings → Code security → Secret scanning → Push protection*.

## Диагностика

| Проблема | Что делать |
|---|---|
| `ModuleNotFoundError: gradio` | установить зависимости: `pip install -r gradio\requirements.txt` |
| `ImportError: DLL load failed` при импорте NumPy | проверить, что установлен `numpy<2`: `pip install "numpy<2" "pandas<2.3"` |
| Порт 7860 занят | `set GRADIO_SERVER_PORT=7861` и запустить снова |
| «Не настроен доступ к сервису.» | проверить `OPENAI_API_KEY` в `gradio/.env` и имя модели |
| «Сервис временно недоступен. Попробуйте позже.» | повторить позже; проверить доступность `LLM_BASE_URL` |
| «Не удалось получить ответ. Попробуйте ещё раз.» | проверить сеть/прокси; при необходимости `LLM_TRUST_ENV=false` |
| «Пустой ответ модели…» | переформулировать запрос или повторить |
